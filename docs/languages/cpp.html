CMake target lws::client C++20 · CMake 3.21+ nlohmann/json · optional libcurl & OpenSSL 3

A synchronous, exception-based C++20 client with value-semantic models and lazy input ranges. Its core depends only on nlohmann/json. HTTP goes through a pluggable lws::HttpTransport (libcurl by default), and cryptography uses OpenSSL 3.

Install

# CMakeLists.txt: fetch and build the library with your project
include(FetchContent)
FetchContent_Declare(lws_client
    GIT_REPOSITORY https://github.com/ebremer/lws-client.git
    GIT_TAG        main
    SOURCE_SUBDIR  cpp)
FetchContent_MakeAvailable(lws_client)
target_link_libraries(app PRIVATE lws::client)

# Or, after `cmake --install`: find_package(lws-client 0.1 CONFIG REQUIRED)
# Dependencies: nlohmann/json (required); libcurl and OpenSSL 3 (optional, see
# LWS_WITH_CURL / LWS_WITH_OPENSSL). vcpkg users get all of them from cpp/vcpkg.json.

The generated lws/config.hpp defines LWS_WITH_CURL and LWS_WITH_OPENSSL as 0/1 so your code can check them.

First program

#include <iostream>
#include <lws/lws.hpp>

int main() {
    auto credentials = lws::SelfSignedCredentials::did_key(lws::PrivateKey::generate(lws::KeyAlgorithm::ES256));
    lws::ClientOptions options;
    options.authenticator = std::make_shared<lws::TokenExchangeAuthenticator>(credentials);
    lws::Client client(options);
    std::cout << "agent:   " << credentials->agent_id() << "\n";

    auto storage = client.discover_storage("http://localhost:8787/root/");
    std::cout << "storage: " << storage.id << "  root: " << storage.storage_root() << "\n";

    auto folder = client.create_container(storage.storage_root(), {.slug = "hello-world"});
    auto file = client.create(folder.location, "Hello, LWS!", "text/plain", {.slug = "hello.txt"});
    std::cout << "created: " << file.location << "\n";

    auto resource = client.read(file.location);
    std::cout << resource.text() << "  (etag " << resource.etag.value_or("-")
              << ", parent " << resource.parent.value_or("-") << ")\n";
}

Configure the client

lws::ClientOptions options;
options.authenticator = std::make_shared<lws::TokenExchangeAuthenticator>(credentials);
options.user_agent = "my-app/1.0";                       // default "lws-client-cpp/0.1.0"
options.default_headers.set("Accept-Language", "en");    // added to every request
options.timeout = std::chrono::seconds(20);
options.max_redirects = 5;                                // credentials are re-checked on every hop
// options.transport = std::make_shared<MyTransport>();  // any lws::HttpTransport (Beast, Qt, …)
lws::Client client(options);                              // immutable, cheap to copy, thread-safe

// Per-call headers
lws::RequestOptions call;
call.headers.set("X-Trace", "1");
auto page = client.read_container(container, call);
std::cout << page.total_items.value_or(-1) << '\n';

Bring your own HTTP stack

Implement lws::HttpTransport::send(const HttpRequest&) → HttpResponse to run the client on Boost.Beast, cpp-httplib, Qt or anything else. The transport must not follow redirects. The client follows them itself so that it can re-evaluate credentials per hop. Client::execute sends a raw request through authentication, the 401 retry and redirect handling without throwing on HTTP errors. execute_checked does throw.

C++ idioms

AspectHow the C++ client does it
CallsSynchronous member functions; Client is immutable, cheap to copy and thread-safe (token cache guarded internally)
PaginationPagedRange<T> input ranges (ContainerRange, TypeRange) that fetch pages on demand; .to_vector()
OptionsAggregates with designated initializers: {.slug = "x"}, {.if_match = etag}, {.recursive = true}
Bodiesstd::string byte buffers (always replayable); no streaming, so use byte ranges for very large resources
ModelsPlain structs with std::optional; JSON as nlohmann::json
Errorslws::Error : std::runtime_error → HttpError → NotFoundError, …; plus AuthenticationError, ProtocolError/ParseError, SignatureVerificationError, TransportError

Headers

Include everything with <lws/lws.hpp>, or pick from client.hpp, models.hpp, auth.hpp, crypto.hpp, keys.hpp, webhook.hpp, notifications.hpp, access.hpp, type_index.hpp, json_patch.hpp, link.hpp, structured_fields.hpp, errors.hpp, http.hpp and constants.hpp.

Notes and deviations

  • The delete operation is remove() because delete is a keyword, and Constraint::op stands in for operator.
  • services_of(type) looks up services because services is the data member.
  • Builder validation (TypeQuery, access documents, subscription requests) throws std::invalid_argument.
  • The library has no HTTP server. WebhookVerifier::verify(method, url, headers, body) plugs into the one you use.
  • ES384 keys are supported for verification in addition to ES256 and EdDSA.
  • When linking static OpenSSL and curl on Windows without vcpkg's toolchain, add ws2_32 and crypt32 yourself.

Build, test and examples

cd cpp
cmake --preset debug             # vcpkg manifest mode (needs VCPKG_ROOT)
cmake --build --preset debug
ctest --preset debug             # LWS_TEST_SERVER=http://localhost:8787 adds the interop test

cmake --preset mingw-debug       # MinGW-w64 with the x64-mingw-static triplet
cmake --preset minimal           # core only: no curl, no OpenSSL

# Examples: lws-quickstart, lws-did-key-auth, lws-verify-webhook
./build/debug/examples/lws-did-key-auth http://localhost:8787/root/
