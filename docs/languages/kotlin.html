Kotlin Kotlin

com.ebremer:lws-client-kotlin 0.1.0 Kotlin 2.2+ · JDK 17+ package com.ebremer.lws.kotlin kotlinx-coroutines, kotlinx-serialization-json

A coroutine-first Kotlin client for the JVM: server applications, command-line tools and desktop programs. Operations are suspend functions, cancelled with the coroutine that calls them; options are named arguments (slug =, ifMatch =, recursive =); listings are cold Flows; errors are one sealed hierarchy under LwsException; documents are kotlinx.serialization JsonElements. HTTP and cryptography come from the JDK itself.

Install

# Until it is on Maven Central: build and install into your local Maven repository (~/.m2)
git clone https://github.com/ebremer/lws-client.git
cd lws-client/kotlin && ./gradlew publishToMavenLocal

# build.gradle.kts
#   repositories { mavenLocal(); mavenCentral() }
#   dependencies { implementation("com.ebremer:lws-client-kotlin:0.1.0") }
# Or build against the checkout, in settings.gradle.kts:
#   includeBuild("path/to/lws-client/kotlin")

# Kotlin 2.2+ on JDK 17+; the only dependencies are kotlinx-coroutines and kotlinx-serialization-json.

The build is Gradle (Kotlin DSL) with the wrapper, in kotlin/; the artifact is com.ebremer:lws-client-kotlin, so it can sit next to the Java client (com.ebremer:lws-client) without a clash. A Gradle build can also include the checkout directly with includeBuild(…), which is how the driver adapter builds against it.

First program

import com.ebremer.lws.kotlin.LwsClient
import com.ebremer.lws.kotlin.auth.SelfSignedCredentials
import com.ebremer.lws.kotlin.auth.SigningKey
import com.ebremer.lws.kotlin.auth.TokenExchangeAuthenticator
import kotlinx.coroutines.runBlocking
import java.net.URI

fun main() = runBlocking {
    val credentials = SelfSignedCredentials.didKey(SigningKey.generateP256())
    val client = LwsClient(authenticator = TokenExchangeAuthenticator(credentials))
    println("agent:   ${credentials.agent}")

    val storage = client.discoverStorage(URI("http://localhost:8787/root/"))
    println("storage: ${storage.id}  root: ${storage.storageRoot()}")

    val folder = client.createContainer(storage.storageRoot(), slug = "hello-world").location
    val file = client.createText(folder, "Hello, LWS!", slug = "hello.txt").location
    println("created: $file")

    val resource = client.read(file)
    println("${resource.text()}  (etag ${resource.etag ?: "-"}, parent ${resource.metadata.parent ?: "-"})")
}

A complete program: runBlocking bridges into coroutines at main; inside a server framework you call the operations from its own coroutines.

Configure the client

val client = LwsClient(
    authenticator = TokenExchangeAuthenticator(credentials),
    userAgent = "my-app/1.0",                           // default "lws-client-kotlin/0.1.0"
    defaultHeaders = mapOf("Accept-Language" to "en"),  // added to every request
    timeout = 20.seconds,                               // per request (each redirect hop)
    maxRedirects = 5,                                   // followed by the client itself (default 10)
    // transport = JdkHttpTransport(myHttpClient),      // or any HttpTransport
)

// Per-call headers and time limits, as named arguments of every operation.
val page = client.readContainer(container, headers = mapOf("X-Trace" to "1"), timeout = 5.seconds)
println(page.totalItems)

// Operations are suspend functions: cancelling the coroutine cancels the request in flight.
val maybe = withTimeoutOrNull(2.seconds) { client.read(url) }

// Another identity over the same transport:
val anonymous = client.withAuthenticator(null)

LwsClient is immutable and safe to share between coroutines and threads: create one and pass it around. withAuthenticator(a) returns a client with a different authenticator over the same transport. The client follows redirects itself and authorizes each hop afresh, so its HttpTransport must not follow redirects. The default JdkHttpTransport runs on java.net.http.HttpClient with Redirect.NEVER (any method, QUERY included); give it your own HttpClient for a proxy, an SSLContext or HTTP/1.1 only. HttpTransport is a fun interface with one suspend fun send(request: HttpRequest): HttpResponse, a few lines over OkHttp or Ktor's client; pass the same transport to TokenExchangeAuthenticator(transport = …) for the metadata and token requests.

Kotlin idioms

AspectHow the Kotlin client does it
Callssuspend functions. Cancelling the calling coroutine (withTimeout, a cancelled scope) cancels the exchange in flight; the timeout option bounds each request and surfaces as TransportException with isTimeout. Concurrent requests that meet the same challenge share one token exchange
OptionsNamed arguments with defaults on every operation: create(c, body, "text/plain", slug = "a.txt", types = listOf(…)), update(url, body, type, ifMatch = etag), delete(url, recursive = true), read(url, range = ByteRange.of(0, 1023)). Every operation also takes headers = and timeout = (a kotlin.time.Duration)
PaginationlistContainer, listTypes, searchAll, listSubscriptions… return a cold Flow: nothing is fetched until it is collected, pages are fetched as collection advances, each collection starts over, and operators such as take(10) fetch only the pages they need
BodiesByteArrays, read whole, so every body can be replayed for the retry after a 401. createText / updateText, createJson / updateJson for a JsonElement; Resource.text() (by the response charset), bytes, json() and decode<T>()
JSONkotlinx.serialization's JsonElement tree, lossless (number literals, member order, {} and []), so documents (linksets, access documents, raw) round-trip unchanged. Build values with buildJsonObject { … } or Json.encodeToJsonElement(value); read a body into a @Serializable class with decode<T>()
ModelsClasses with val properties (meta.etag, page.items, item.isContainer); computed values that can fail are functions (storageRoot()). URLs are java.net.URIs, absolute in every result; type IRIs are strings
ErrorsLwsException, a sealed RuntimeException: HttpException with a subclass per status (NotFoundException, ConflictException, PreconditionFailedException, …), AuthenticationException, ProtocolException, SignatureVerificationException, TransportException, so a when over it is exhaustive. Caller mistakes are Kotlin's own IllegalArgumentException, thrown before any request
CryptoThe JDK's providers: SHA256withECDSAinP1363Format for ES256 (JOSE's raw r‖s directly), Ed25519 for EdDSA, MessageDigest for SHA-256 and SHA-512. Keys convert to and from JCA key pairs (SigningKey.of(keyPair), toKeyPair())
SecretsKeys, tokens and credentials stay out of toString(), so logging a client, an authenticator or a key shows no secret

Notes and deviations

  • The package is com.ebremer.lws.kotlin, not the Java client's com.ebremer.lws, so both libraries can be on one classpath. Link.typeLink(iri) builds a rel="type" link, since type is the property of the type attribute. A subscription's URL (the contract's subscription) is Subscription.url. An activity's object is activity.`object`, as object is a keyword.
  • The contract's error classes are exception classes named …Exception (NotFoundException, ProtocolException); the 501 one is NotImplementedException, which shadows nothing that Kotlin imports by default. Their constructors are internal: HttpException.fromResponse(…) builds the right one, for a transport or a test double.
  • Bodies are byte arrays: there is no streaming read or upload, so every body can be replayed for the single retry after a 401. Read large resources in pieces with range =.
  • JsonPatch, TypeQuery and Linkset are builders that change in place: doc.linkset.add(…), then updateLinkset(doc.url, doc.linkset); TypeQuery.copy() takes a snapshot. JsonPatch has overloads for strings, numbers and booleans, and jsonPatch { replace("/done", true) } builds one. TypeQuery's builders throw IllegalArgumentException for an IRI that is not absolute or an empty OR group.
  • WebhookVerifier.verify(method, inbox, headers, body) takes the parts of a delivery, the headers as Headers or a Map<String, List<String>>, so any server framework can pass its request on; verifyExchange(exchange, inbox) takes a request of the JDK's built-in com.sun.net.httpserver server. Pass the inbox URL as registered, not the one a proxy forwarded to.
  • Clocks are java.time.Clocks (TokenExchangeAuthenticator(clock = …), WebhookVerifier(clock = …), SelfSignedCredentials.withClock(…)), for tests; instants are java.time.Instants and durations kotlin.time.Durations.
  • Extras: request(method, url, body, contentType) sends any method through the authentication and redirect pipeline; readLinksetResource(url) reads a linkset at a known URL; TokenExchangeAuthenticator.accessToken(asUri, realm) obtains a token ahead of time.

Build, test and examples

cd kotlin
./gradlew build                                         # unit, fixture and HTTP tests, the examples, the jars
node ../testing/mock-server/server.mjs --port 8787 &
LWS_TEST_SERVER=http://localhost:8787 ./gradlew test    # adds the cross-language interop scenario

# Examples (src/examples/kotlin): Quickstart.kt, SelfSignedAuth.kt, WebhookReceiver.kt
./gradlew -q quickstart --args=http://localhost:8787/root/

The compiler runs in explicit API mode with warnings as errors, against the Java 17 API (-Xjdk-release=17) and the Kotlin 2.2 language and API level, so the library works with Kotlin 2.2 and later on any JDK from 17.
