Access requests & grants

An agent asks for access by posting an AccessRequest to the storage's AccessRequestService. A storage controller records a decision as an AccessGrant, and the server then adjusts its access policies. Grants are records of what was allowed, not tokens you present.

The access profile

{
  "@context": ["https://www.w3.org/ns/lws/v1"],
  "type": ["AccessRequest"],
  "storage": "https://storage.example/",
  "inbox": "https://id.example/agent/inbox/",
  "access": [{
    "type": ["AccessPolicy"],
    "action": ["read", "create"],
    "assignee": "https://id.example/agent",
    "target": { "type": "StorageResource", "value": ["https://storage.example/root/projects/"] },
    "constraint": [
      { "leftOperand": "purpose", "operator": "eq", "rightOperand": "https://purpose.example/collaboration" },
      { "leftOperand": "dateTime", "operator": "lteq", "rightOperand": "2026-12-31T23:59:59Z" }
    ]
  }]
}
MemberMeaning
actionread (GET/HEAD), modify (PUT/PATCH), create (POST), delete (DELETE)
assigneeThe agent requesting or receiving access; http://xmlns.com/foaf/0.1/Agent means everyone
targetStorageResource, Container or DataResource matcher plus resource URLs
constraintAll must hold. Operands are purpose, client, format, type and dateTime; operators are eq, isAnyOf, gteq and lteq

Constraint helpers

Helper (concept)Produces
purpose(uri) / purposeAnyOf(uris)purpose eq / purpose isAnyOf
client(clientId)client eq: limit access to one application
format(mediaType) / formatAnyOf(types)format eq / isAnyOf
type(iri) / typeAnyOf(iris)type eq / isAnyOf (Rust and Python: resource_type…)
notBefore(time) / notAfter(time)dateTime gteq / dateTime lteq (an access window)

Granting and revoking

Creating grants is normally reserved to the storage controller. Revoking a grant (DELETE) tells the server to withdraw the permissions it recorded.

// A storage controller approves a request by recording a grant with the same policy model.
AccessRequest pending = client.getAccessRequest(requestUrl);
URI grants = storage.accessGrantService().orElseThrow().serviceEndpoint();
URI grantUrl = client.grantAccess(grants, AccessGrant.approving(pending));

client.listAccessGrants(grants).forEach(g -> System.out.println(g.id()));
client.revokeAccessGrant(grantUrl);   // the server withdraws the underlying permissions
// A storage controller approves a request by recording a grant with the same policy model.
const pending = await client.getAccessRequest(requestUrl);
const grants = storage.accessGrantService()!;
const grantUrl = await client.grantAccess(grants, new AccessGrant({
  storage: pending.storage,
  access: [...pending.access],
}));

for await (const g of client.listAccessGrants(grants)) console.log(g.id);
await client.revokeAccessGrant(grantUrl);   // the server withdraws the underlying permissions

Notifications If a request or grant has an inbox, the server should notify it: the controller about new requests, and the requester when a grant is created. These deliveries use the LWS notification format, so you can verify them with the same webhook verifier.
