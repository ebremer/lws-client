Containers & pagination

A container lists its members in an application/lws+json representation. Large containers are split into pages linked with first, next, prev and last. The clients give you one page at a time, or a lazy sequence over all of them.

The container representation

{
  "@context": "https://www.w3.org/ns/lws/v1",
  "id": "/alice/photos/",
  "type": "Container",
  "totalItems": 150,
  "items": [
    { "type": "DataResource", "id": "/alice/photos/vacation.jpg",
      "format": "image/jpeg", "size": 248392, "modified": "2025-11-20T10:30:00Z" },
    { "type": "Container", "id": "albums/" }
  ]
}
FieldModel propertyNotes
ididResolved to an absolute URL
typetypesAlways a list. Container, lws:Container and the full IRI all match isContainer()
totalItemstotalItemsAll visible members across pages; may be approximate (optional or -1 in Go when absent)
itemsitemsThis page's members as ContainedResource
formatformatMedia type; required for data resources
size / modifiedsize / modifiedOptional. An unparseable date never fails the listing (the raw string is kept)

Relative identifiers Servers may return path-relative ids such as /alice/photos/ or albums/. The clients always resolve them against the response URL, so every id you receive is absolute and can be passed straight to read.

Reading one page

readContainer returns a single page with its pagination links and response metadata. Page URLs are opaque: follow them, but never construct them.

ContainerPage page = client.readContainer(container);
System.out.println(page.id() + " " + page.totalItems() + " " + page.etag());
for (ContainedResource item : page.items()) {
    System.out.println(item.id() + " " + (item.isContainer() ? "container" : item.format().orElse("?"))
            + " " + item.size() + " " + item.modified());
}
page.next().ifPresent(next ->                        // opaque, server-issued URL
        System.out.println(client.readContainer(next).items().size()));
const page = await client.readContainer(container);
console.log(page.id, page.totalItems, page.metadata.etag);
for (const item of page.items) {
  console.log(item.id, item.isContainer() ? "container" : item.format, item.size, item.modified);
}
if (page.next) {
  const nextPage = await client.readContainer(page.next);   // opaque, server-issued URL
  console.log(nextPage.items.length);
}
lws::ContainerPage page = client.read_container(container);
std::cout << page.id << ' ' << page.total_items.value_or(-1) << ' ' << page.metadata.etag.value_or("") << '\n';
for (const lws::ContainedResource& item : page.items) {
    std::cout << item.id << ' ' << (item.is_container() ? "container" : item.format.value_or("?")) << ' '
              << item.size.value_or(-1) << ' ' << item.modified_raw.value_or("") << '\n';
}
if (page.next) {
    auto next_page = client.read_container(*page.next);   // opaque, server-issued URL
    std::cout << next_page.items.size() << '\n';
}
let page = client.read_container(container).await?;
println!("{} {:?} {:?}", page.id, page.total_items, page.metadata.etag);
for item in &page.items {
    println!("{} {} {:?} {:?} {:?}", item.id, item.is_container(), item.format, item.size, item.modified);
}
if let Some(next) = &page.next {
    let next_page = client.read_container(next).await?;   // opaque, server-issued URL
    println!("{}", next_page.items.len());
}
page, err := client.ReadContainer(ctx, container)
if err != nil {
	return err
}
fmt.Println(page.ID, page.TotalItems, page.Metadata.ETag) // TotalItems is -1 when absent
for _, item := range page.Items {
	fmt.Println(item.ID, item.IsContainer(), item.Format, item.Size, item.Modified)
}
if page.Next != "" {
	next, err := client.ReadContainer(ctx, page.Next) // opaque, server-issued URL
	if err != nil {
		return err
	}
	fmt.Println(len(next.Items))
}
page = client.read_container(container)
print(page.id, page.total_items, page.metadata.etag)
for item in page.items:
    kind = "container" if item.is_container else item.format
    print(item.id, kind, item.size, item.modified)
if page.next:
    next_page = client.read_container(page.next)   # opaque, server-issued URL
    print(len(next_page.items))
ContainerPage page = await client.ReadContainerAsync(container);
Console.WriteLine($"{page.Id} {page.TotalItems} {page.ETag}");
foreach (ContainedResource item in page.Items)
{
    Console.WriteLine($"{item.Id} {(item.IsContainer ? "container" : item.Format)} {item.Size} {item.Modified}");
}
if (page.Next is { } next)                           // opaque, server-issued URL
    Console.WriteLine((await client.ReadContainerAsync(next)).Items.Count);

The clients accept the three equivalent container media types (application/lws+json, application/ld+json, application/json). Any other content type, or a body whose type is not a container, is reported as a protocol error.

Iterating every member

listContainer follows rel="next" lazily. A page is only fetched when you iterate past the previous one, so you can stop early without loading the rest. Each language uses its native lazy-sequence type:

LanguageType returned by listContainer
JavaStream<ContainedResource> (lazy, spliterator-backed)
TypeScriptAsyncGenerator<ContainedResource> (for await)
C++lws::ContainerRange, a C++20 input range (for (auto& item : …), .to_vector())
RustLwsStream<ContainedResource>, a futures::Stream (try_next, try_collect)
Goiter.Seq2[ContainedResource, error] (for item, err := range …)
PythonIterator[ContainedResource]; AsyncIterator on AsyncLwsClient
C#IAsyncEnumerable<ContainedResource> (await foreach, System.Linq.AsyncEnumerable operators)
// A lazy Stream: pages are fetched only as the stream is consumed.
client.listContainer(container)
        .filter(item -> item.hasType("https://schema.org/Person"))
        .forEach(item -> System.out.println(item.id()));

List<URI> ids = client.listContainer(container).map(ContainedResource::id).toList();
// Lazily follows rel="next": pages are fetched only as you iterate.
for await (const item of client.listContainer(container)) {
  if (item.hasType("https://schema.org/Person")) console.log(item.id);
}

// Collect everything
const ids: string[] = [];
for await (const item of client.listContainer(container)) ids.push(item.id);
// A lazy input range: pages are fetched only as you iterate.
for (const lws::ContainedResource& item : client.list_container(container)) {
    if (item.has_type("https://schema.org/Person")) std::cout << item.id << '\n';
}

std::vector<lws::ContainedResource> all = client.list_container(container).to_vector();
// A lazy Stream: pages are fetched only as you poll it.
let mut items = client.list_container(container);
while let Some(item) = items.try_next().await? {
    if item.has_type("https://schema.org/Person") {
        println!("{}", item.id);
    }
}

let all: Vec<ContainedResource> = client.list_container(container).try_collect().await?;
// Lazily follows rel="next": pages are fetched only as you iterate.
for item, err := range client.ListContainer(ctx, container) {
	if err != nil {
		return err
	}
	if item.HasType("https://schema.org/Person") {
		fmt.Println(item.ID)
	}
}
# Lazily follows rel="next": pages are fetched only as you iterate.
for item in client.list_container(container):
    if item.has_type("https://schema.org/Person"):
        print(item.id)

ids = [item.id for item in client.list_container(container)]
# AsyncLwsClient: async for item in client.list_container(container): ...
// A lazy IAsyncEnumerable: pages are fetched only as the enumeration advances.
await foreach (ContainedResource item in client.ListContainerAsync(container))
{
    if (item.HasType("https://schema.org/Person")) Console.WriteLine(item.Id);
}

// .NET 10's System.Linq.AsyncEnumerable operators work on every listing.
List<Uri> ids = await client.ListContainerAsync(container).Select(item => item.Id).ToListAsync();

What you can see

If you can read a container, its listing includes every member you can access. It may also list members you cannot read. Being able to list a container does not imply access to its members, and access to a member does not imply you can list its container. Expect 403 or 404 when you follow ids from a listing.

Other listings use the same model

Subscriptions, access requests and access grants are exposed as LWS containers too, and type search results use the same ContainerPage shape. The same pagination helpers (listSubscriptions, listAccessRequests, searchAll…) work for all of them.
